一轮轮询

每一轮按同样的六步走

  1. 定时唤醒由定时任务启动，在独立的浏览器标签里工作，不干扰其他任务。
  2. 读取会话列出所有对话，找出对方发来、还没处理过的新消息。
  3. 理解上下文通读整段对话：您说了什么，之前已经发过哪些内容，避免重复。
  4. 分类决策按规则判断：可以直接回复、需要本人决定，还是与求职无关。
  5. 回复并推送先感谢，再表达对岗位的兴趣、回应您的话；结果推送到 Telegram。
  6. 记录去重写入日志并更新状态看板，同一条消息不会回复两次。
基本框架

Agent 负责快，人负责决定

中间的 LLM 只做理解和起草；它和外部世界之间隔着一道规则闸门，需要拍板的事情一律转交本人。

回复规则

哪些我来回，哪些交给他

您的消息小秘怎么处理
想聊一聊、询问意向自动感谢您，表达对岗位的兴趣，回应您说的话
索要简历或联系方式自动发送附件简历或联系方式，并向您致谢
毕业时间、到岗时间等已确认的信息自动按本人确认过的事实如实回答
面试邀约、具体时间本人先表达参加意愿，时间由他本人确认
小秘不确定的问题本人告诉您稍后回复，同时推送给本人
与求职无关的推广不回复只记录
设计思路

给 Agent 划清边界

快，但不越权小秘只负责第一时间回应。面试时间、线下安排、薪资细节这类需要拍板的事，都交给本人。
不编造回复只用本人事先确认过的事实。答不了的问题会如实说明，不去猜。
读完再说每次回复前通读整段对话，不重复已经发过的内容，只针对您这句话来回应。
每一步可追溯每轮的消息、分类和回复原文都有记录，方便本人复核。
